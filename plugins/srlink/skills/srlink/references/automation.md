# SRlink: background registration

Read when the user asks to sync their posts, about the background check, the session scan, or missing handles. Commands below are `srlink <command>` = `node <skill folder>/scripts/srlink.cjs <command>`.

## My new posts (automatic for YouTube)

- `srlink sync` registers the newest (up to 10, last 30 days) videos of the user's YouTube channel that SRlink has not seen: title without hashtags, a 3-5 sentence summary from the description, the YouTube publish time. `srlink schedule on [H]` runs it in the background every H hours (1-24, default 1). A video already registered, or one the user deleted on SRlink, is never registered again.
- Rednote, LinkedIn, X, TikTok, Instagram and Reddit have no public feed. When the user asks ("sync my posts"), open their profile in Chrome, take the newest posts, and register the ones not in `srlink mine` with `srlink share` (Rednote: the Copy Link share URL, see section 2).
- Session scan (`srlink scan on`): each background run also reads this computer's Claude Code session files changed since the last run (the first run: the past 24 hours) for YouTube links (local only; nothing but the links leaves). A video is checked with YouTube's public oEmbed: the user's own, published in the last 30 days -> registered. Other platforms' links are not collected and old posts are not backfilled: a Rednote / LinkedIn / X post reaches SRlink when it is published in a session (the hook, see [publish](publish.md)), or by Submit manually on srlink.app.
- Scheduled posts' links (`srlink auto-fill on|off`, default on; owner 2026-11-19): when a scheduled LinkedIn / X / Rednote / TikTok post's time has passed and its card still has no link, each background run starts a headless Claude Code (`claude -p --chrome`) that runs `srlink due --steps` in the user's own Chrome, so the link lands within the hour after the scheduled time even with no session open. Hourly for the first 6 hours, then every 6 hours until the server stops listing it (3 days). That Claude may only use the Chrome tools and this CLI (everything else is denied), never posts, comments, likes, follows or messages, and stops at any login or captcha. It needs Claude Code with Claude in Chrome and Chrome open; otherwise the next Claude session fills the link (the hook). Results go to `~/.srlink/sync.log`.
- Missing handles (`srlink match`, also in each background run): when a member comments on the user's post through the SRlink feed, SRlink keeps that comment's text. If the member has no account name on that platform, YouTube comments are read without a browser, the matching comment's writer is reported (`srlink claim <postId> <personId> <platform> <handle>`), and the member's handle is filled in and the comment marked verified. Rednote / LinkedIn / X / TikTok / Instagram / Reddit ones are handed to Claude at session start to find in Chrome. The server refuses a handle someone already uses; never claim the user's own account for a member.
- Session-start reminders (comments to claim) arrive only in AIs with the plugin. Elsewhere, when the user asks, run `srlink match` yourself and do the same checks.
